1. Inventory every compiler emission family and BytecodeBuilder post-pass, then map each opcode to BytecodeLifter, CFA, SSA, ASTLifter, rewriters, and source generation.

3. After the source audit, take candidates one at a time: reduced source → failing public decompile/compile/VM parity test (red) → narrow root-cause fix (green) → neighbouring shapes and full regression suite. Mark ambiguous or unrecoverable source constructs separately.

States: `unchecked`, `source-consistent`, `candidate`, `confirmed`, `fixed`, `shelved`, `unrecoverable`. “Source-consistent” means no source-level contradiction found; it does not prove semantic parity.

## Candidates and resolutions

Add one entry per distinct suspected root cause, including compiler path, Fission path, counterexample, first wrong stage, test, fix, and verification result.

### C1 — `GETIMPORT` constant operand truncated in lifted IR (`fixed`)

`Compiler.cpp:2900-2912,3009-3022` emits `LOP_GETIMPORT` in AD format with a constant-table index `D` up to 32767, plus an AUX import path. `BytecodeLifter.cpp:489-496` stores `GetABCOperand(B)` in lifted operand 1. This preserves only one byte of the index. AST source reconstruction at `ASTLifterExpressions.cpp:320-346` uses AUX and does not read operand 1, so observable decompilation may survive; lifted IR is inaccurate when import constant index exceeds 255. Need first confirm emitted high-index import is compiler-reachable, then write a BytecodeLifter regression and fix one operand decode.

**Red/green:** Compiler-generated source with 270 distinct string constants and a final `math.pi` emits a `GETIMPORT` with raw D=274. Lifted IR reported 18 (low byte) before fix. Regression asserts decoded IR constant index equals raw D; `BytecodeLifter` now reads `GetD()`. Focused test passes (7 assertions, GCC Debug). Full suite pending.

### C2 — `DUPTABLE` template shape versus reconstructed field insertion order (`source-consistent`)

Compiler `compileExprTable` builds one template from record keys and last values; dynamic fields become nil placeholders, then emitted stores in source order (`Compiler.cpp:2695-2845`). Fission seeds the exact template keys and constant values as literal fields (`ASTLifterExpressions.cpp:752-772`). Crucially, it immediately returns from `LiftTableLiteral` for nonempty `DUPTABLE`, so it **does not fold later stores into that literal**. Subsequent stores remain statements in bytecode order. Recompiled literal preserves template key slots and dynamic stores remain after it. Original insertion-order concern was based on overlooking the early return; no demonstrated divergence. Keep table row open for `NEWTABLE`/`SETLIST` semantics.

### C3 — `FASTCALL3` register operands written through immediate union member (`fixed`)

Compiler encodes second/third argument registers in AUX bytes (`Compiler.cpp:811-917`); `math.clamp(x, lo, hi)` reaches this opcode (`Builtins.cpp:160-161`, `Compiler.cpp:1460-1480`). Before fix, `BytecodeLifter.cpp:1072-1091` marked lifted operands 3/4 as `Register` but wrote `value.imm.n`, leaving SSA and validation to read an inactive union member (`BytecodeLifter.hpp:100-115`). Both writes now use `value.reg`. This is a narrow exception to the red-test rule: on the current little-endian host the low byte was already correct, UBSan has no active-union-member check, and a big-endian execution target is unavailable. A temporary compiler-produced `math.clamp` probe emitted `FASTCALL3 #, R0, #, R1, R2`; original and lifted VM traces both returned `1`. No observable parity change is claimed. Full CTest 632/632 and stress samples 22/22; no vacuous permanent test was added.

### C4 — numeric `for` CFG jump targets appear one instruction early (`source-consistent abstraction`)

Compiler `compileStatFor` emits `FORNPREP` targeting the instruction after `FORNLOOP`, and `FORNLOOP` targeting the first body instruction (`Compiler.cpp:4277-4346`). `BytecodeBuilder::patchJumpD` stores `target - source - 1` (`BytecodeBuilder.cpp:610-638`); VM adds `D` after incrementing `pc` (`VM/src/lvmexecute.cpp:2529-2571`). Fission preserves raw `D` for both opcodes (`BytecodeLifter.cpp:1030-1048`) and `ControlFlowAnalyzer::GetJumpOffset` deliberately uses raw `D` as a pointer-relative offset (`ControlFlowAnalyzer.cpp:53-70`), routing prep's failed check through the latch and the latch back through prep. `BytecodeLifter.cpp:1660-1680` explicitly increments prep offset when the shorthand does not land on matching `FORNLOOP` (e.g. jump threading). SSA comments and liveness (`SSABuilder.cpp:222-248`) treat prep reads as entry-only and omit them on latch edges. This is a CFG abstraction, not a missing `+1` fix. Still assess whether folded/trampolined loops violate its assumptions, but do not modify offset unconditionally.

### C5 — legacy type encoding v1 skips extra bytes (`fixed`)

Current `BytecodeBuilder::writeFunction` emits type encoding v3, but Fission accepts v1-v3. Luau VM's v1 decoder copies `typesize` bytes, then advances by exactly `typesize` (`VM/src/lvmload.cpp:392-428`). Fission copies `typeSize` but advances by `headerSize + typeSize` (`Deserializer.cpp:104-127`); the synthetic v2 header exists only in memory. Valid v1 blobs with type metadata should lose their instruction-count prefix and fail or misparse. This is outside current compiler output but inside declared version support. After audit, make a small v1 bytecode fixture through existing builder/manual encoding, prove red, then correct advancement.

**Red/green:** `LegacyTypeEncodingRegression.cpp` builds a v12/type-v1 blob with a two-byte function type and one `RETURN`. Luau VM accepts and executes it; Fission returned no decoded bytecode before fix. Deserializer now advances over `typeSize` only after copying into its synthetic v2-compatible buffer. Focused test passes (4 assertions, GCC Debug). Full suite pending.

### C6 — generic `FORGLOOP` SSA omits state/index reads (`fixed`)

Compiler `compileStatForIn` initializes generator/state/index at `A..A+2` and emits `FORGLOOP` (`Compiler.cpp:4348-4457`). VM's `FORGLOOP` reads all three (`VM/src/lvmexecute.cpp:2704-2808`). Fission recorded only explicit A; liveness and SSA implicit uses omitted A+1/A+2. A compiler-produced generic loop proved this in a red regression: no `FORGLOOP` implicit-use entry. SSA now records all three reads before its control and loop-variable writes; the SSA oracle models matching VM reads. Latch-carried control phis also required `FORGPREP` to use its entry-edge value, and ASTLifter to recognize the original nil control initializer. Focused test is green (7 assertions); full CTest passed 628/628 and sample stress passed 22/22 after formatting.

### C7 — dead-local rewrite treats global reads as effect-free (`fixed`)

Compiler does not remove a nonconstant `local unused = global` at O1: `areLocalsRedundant` requires constant locals (`Compiler.cpp:4045-4070`), so it emits `GETGLOBAL` or `GETIMPORT`. Fission `DeadLocalEliminator::IsPure` returned true for every `IdentifierExpressionNode`, including `GlobalIdentifier` with `bIsGlobal=true` (`DeadLocalEliminator.hpp:116-124`, `ASTLifterShared.hpp:13-18`), and `RewriteStatements` dropped unread pure declarations (`DeadLocalEliminator.hpp:27-43`). Luau GETGLOBAL may invoke the environment's `__index` metamethod and raise or mutate state; GETIMPORT may resolve dynamically after environment invalidation.

**Red/green:** `CompilerLiftingAuditRegressions.cpp` compiles `local unused = watched; print('after')` and runs both bytecodes under an environment `__index` that prints on `watched`. Before fix, original trace was `"read watched"; "after"`; decompiled trace only `"after"` because generated source discarded the declaration. `DeadLocalEliminator::IsPure` now permits identifier reads only when `bIsGlobal` is false. Focused test passes after fix (4 assertions, GCC Debug). Full suite pending.

### C13 — bounded CFA loop-exit tracing (`candidate`)

`ControlFlowAnalyzer::IdentifyStructuresInternal` follows at most eight post-latch jump/NOP bridges when locating a loop exit (`ControlFlowAnalyzer.cpp:585-614`), at most sixteen single-successor blocks when joining exits after O2 inlining (`:619-664`), and at most eight jump/NOP blocks when classifying a forward jump as `continue` (`:1211-1234`). `BytecodeBuilder::foldJumps` may collapse ordinary jump chains; compiler output can still contain intervening non-collapsible blocks. Need derive a compiler-produced loop with a longer chain before calling these caps a defect. An unbounded graph walk with visited-set would be the narrow fix only if a counterexample reaches a cap.

**Directed probe:** Ten nested `if/else` arms around a `repeat` at O0 and O1 produced many branch blocks. The O0 post-latch exit was directly visible to `exitAt`; O1 jump folding produced return blocks. Both decompiled successfully with the same apparent branch and loop behavior. This does not exercise any hop cap and is not a regression test.

**Long-jump follow-up:** A compiler-produced O0 program with 36,000 independent assignments in a cold branch emitted `LOP_JUMPX`. Luau's `BytecodeBuilder::foldJumps` skips forwarding-jump folding when a long jump exists. CFA retained eleven forwarding blocks between a jump and loop latch; the distant jump stayed `Standard` beyond the eight-hop `continue` bound. Decompiled output recompiled and matched VM trace on this case. This proves the cap is reachable but not a semantic failure. Temporary structural probe removed; C13 remains a candidate.

**Post-loop effect check:** Added `print("after", x)` between that loop and its return in a temporary copy of the same compiler-produced source. Original and decompiled VM traces matched `"after" 1; return 1` at O0/O1/O2. The O0 case retains the prior long-jump and forwarding-chain shape, so the observed eight-hop classification limit did not drop this post-loop effect. The temporary source is ignored and no passing-only test was added.

**Producer check:** Luau `AstStatContinue` emits one `LOP_JUMP` and the loop compiler patches it to its continuation label (`Compiler.cpp:4806-4824,4249-4256`; repeat uses `:3941-3975`). The observed eleven-bridge jump came from nested `if/else` joins, not a source `continue`; classifying it `Standard` was appropriate. A long chain can still matter to `exitAfterLatch` or `joinedExit`, so C13 stays open for those paths rather than treating the observed cap hit as a failure.

### C14 — repeat exit fallback selects unrelated return (`candidate`)

When a repeat latch has no identified exit, `ControlFlowAnalyzer.cpp:1084-1117` scans *all* basic blocks and assigns the first `Return`, without checking reachability from the repeat condition. Compiler `compileStatRepeat` emits condition branching over a `JUMPBACK` to post-loop code (`Compiler/src/Compiler.cpp:3873-3973`); ASTLifter trusts recorded non-latch exits (`ASTLifter.cpp:1598-1607`). This fallback is suspicious, but a compiler-produced route into it remains unproved. Do not change it without a red example.

**Directed probe:** Luau-compiled `if early then return 1 end; repeat until cond; print('after'); if flag then print('flag') end; return 2` inside a function decompiled to the same control flow. Original and output both printed `after` and returned 2 for `early=false,cond=true,flag=false` (GCC Debug, 4 assertions). The source-level fallback concern did not produce a behavior mismatch in this shape; the temporary test was removed.

**Source follow-up:** Luau places the normal repeat exit at `skipLabel` after `JUMPBACK` (`Compiler.cpp:3947-3968`); CFA usually finds it from escaping successors or `exitAfterLatch` (`ControlFlowAnalyzer.cpp:583-614,732-747`). The global first-`Return` fallback remains suspect if those routes fail, but no compiler-produced route to that failure was found. Do not remove the prior `c587d2702` header-successor guard without a red case; it protects compound conditions.

**Structural follow-up:** Compiled six repeat shapes with an earlier guard `return`, a post-loop `print` and final `return`, at O0/O1/O2: empty body; printed body; `or` exit; `and` exit; `break`; `continue`. For every shape CFA classified as repeat, its `loopExit` began after the latch, never at the earlier guard return (117 passing assertions in temporary probe). `repeat until cond and other` was emitted as equivalent `while true do if cond and other then break end end`, so a requirement that it retain the repeat classification was invalid. No C14 counterexample found; temporary probe removed rather than retaining a shape smoke test.

**Constant-false follow-up:** A compiler-produced `repeat n += 1; if n == 2 then break end until false` with an earlier unrelated `return`, a post-loop print, and both early/normal calls matched original VM traces at O0/O1/O2. CFA chose the post-loop block as exit through the break condition. ### C21 — computed table fields can truncate a trailing variadic list (`fixed`)
